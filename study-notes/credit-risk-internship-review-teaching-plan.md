# 第 1 课：银行到底在预测什么？

## 1.1 业务问题

本次实习的核心问题可抽象为：

> 对当前仍处于正常或可观察状态的客户/贷款，预测未来一段时间内发生逾期或信用质量恶化的概率。

机器学习上，这是一个二分类问题：

```text
0 = Good / 未发生目标风险事件
1 = Bad / 发生逾期或目标风险事件
```

模型真正输出的不是“会/不会”两个字，而是：

```text
P(default)
```

即违约/逾期概率。

## 1.2 为什么概率比直接分类更重要？

例如：

```text
客户 A：0.002
客户 B：0.081
客户 C：0.437
客户 D：0.861
```

即使最终都可以被二值化为 0/1，银行仍然更关心风险排序，因为风险管理通常需要：

- 排出高风险客户名单；
- 分配催收或贷后资源；
- 设置不同审批策略；
- 转换为内部信用评分；
- 做分层管理。

### 本课自检

- 为什么信贷模型的核心不只是“分类准确率”？
- 为什么概率排序比单个 0/1 标签更有业务价值？
- 如果一个模型所有客户都预测为正常，但准确率达到 99%，为什么仍可能毫无价值？

# 第 2 课：Observation Date、Performance Window 与标签

## 2.1 Observation Date

Observation Date 是“站在哪一天看客户”。

在该时点只能使用当时已经能够获得的信息，例如：

- 贷款金额；
- 贷款余额；
- 利率；
- 还款方式；
- 担保方式；
- 贷款用途；
- 已发生的历史行为。

这些构成模型的输入：

```text
X
```

## 2.2 Performance Window

接下来要观察未来一段时期，例如未来 6 个月。

如果未来窗口内发生目标逾期：

```text
Y = 1
```

否则：

```text
Y = 0
```

因此严格监督学习样本应为：

```text
X(观察时点)
    ↓
预测
    ↓
Y(未来表现窗口)
```

## 2.3 本次实习中真正遇到的问题

早期检查贷款账户数据时发现，核心贷款账户表的统计日期基本集中在单一时点，例如：

```text
stat_dt = 2026-04-30
```

这意味着：

- 可以获得当前特征；
- 但无法仅凭该快照自动得到“之后 6 个月是否逾期”的真实标签。

因此项目中进一步搜索历史逾期明细、风险表等数据来源，并检查历史逾期表中的：

- 贷款账号；
- 逾期类型；
- 逾期编号；
- 逾期日期；
- 应还金额；
- 实还金额；
- 起止日期等。

这一过程体现了一个重要认知：

> 在真实风控项目中，标签构造往往比选择算法更难。

## 2.4 后期完整版本中的时间数据思路

后期代码中进一步出现了多期特征/标签文件，例如 2024-12、2025-06、2025-12 等时间快照，并使用固定时间阈值做时序切分。

示例逻辑：

```text
TRAIN：较早时间
VALIDATION：中间时期
TEST：更晚时期
```

而不是简单随机拆分。

### 本课任务

用自己的话写出：

1. Observation Window 是什么？
2. Performance Window 是什么？
3. 为什么只有一个日期的快照不能严格训练未来逾期模型？
4. 为什么标签是风控建模中最容易出问题的环节之一？

# 第 3 课：数据审计与数据泄漏

## 3.1 数据进入模型前必须检查什么？

至少检查：

- 数据类型；
- 缺失率；
- 唯一值个数；
- 常量字段；
- 极高缺失字段；
- 可疑未来字段；
- 业务含义；
- 是否属于标签泄漏。

项目中实际做过类似审计：

```text
dtype
missing_count
missing_rate_pct
unique_count
```

## 3.2 缺失值

真实数据中部分字段缺失率很高，例如某些字段达到 40%–50%，甚至接近 100%。

必须判断：

```text
保留？
删除？
中位数填充？
类别编码？
增加 missing flag？
```

## 3.3 常量字段

如果：

```text
unique_count = 1
```

该字段几乎无法提供区分信息。

## 3.4 数据泄漏

对于“预测未来是否逾期”的任务，必须重点审计类似：

- 当前逾期标识；
- 当前逾期天数；
- 已有风险评级；
- 未来才能获得的字段；
- 事后生成字段。

核心判断原则：

> At prediction time, do I know this variable?

如果预测时点无法知道，却被放进模型，就可能发生 Data Leakage。

### 本课自检

判断以下字段是否可能泄漏：

- 当前贷款余额；
- 当前执行利率；
- 未来 3 个月逾期次数；
- 未来最终风险评级；
- 观察日前累计历史还款次数。

# 第 4 课：特征工程

## 4.1 原始业务字段

实习中涉及的典型变量包括：

- 贷款金额；
- 贷款余额；
- 基准/执行利率；
- 客户类型；
- 贷款类型；
- 贷款用途；
- 还款方式；
- 还款频率；
- 担保方式；
- 产品数量；
- 贷款期限；
- 日期字段等。

## 4.2 典型业务衍生特征

### balance_ratio

贷款余额与贷款金额之间的比例关系，用于表达尚未偿还的贷款压力。

### repayment_ratio

一种构造形式：

```text
1 - ln_bal / ln_amt
```

表示贷款已偿还比例。

### loan_term_days

```text
到期日 - 开户日
```

表示贷款总期限。

### loan_age_days

```text
观察日 - 开户日
```

表示贷款已经存续多久。

### loan_age_ratio

```text
已存续时间 / 总期限
```

表示当前处于贷款生命周期的哪个阶段。

### remaining_term_ratio

```text
1 - loan_age_ratio
```

表示剩余期限比例。

### rate_difference

执行利率与基准/参考利率之间的差异。

### loan_balance_pressure

用于表达贷款余额压力的衍生指标。

### loan_term_level

将连续的贷款期限转为短期/中期/长期等分层指标。

### high_balance_flag

例如：

```text
ln_bal > ln_bal 的中位数
```

则标记为 1，否则为 0。

## 4.3 为什么只有二三十个业务字段，却能变成 499 个模型特征？

主要原因是 One-Hot Encoding。

例如贷款用途：

```text
购房
汽车
经营
教育
消费
装修
...
```

编码后会变成：

```text
ln_use_购房
ln_use_汽车
ln_use_经营
ln_use_教育
...
```

若某个类别变量本身有数百种取值，则一个原始变量就可能展开为数百列。

因此应准确表述：

> 原始字段经过类别编码后形成约 499 维模型输入空间，而不是“手工构造了 499 个业务特征”。

本次原型阶段中，后续加入业务衍生特征后，模型维度进一步增长，并增加缺失标记等信息。

## 4.4 Missing Indicator

对于高缺失字段，可以增加：

```text
feature_missing = 1 / 0
```

因为“是否缺失”本身有时也是风险信息。

### 本课任务

对每个衍生特征回答两个问题：

1. 它从哪些原始字段构造？
2. 它试图表达什么业务风险？

# 第 5 课：时间切分与类别不平衡

## 5.1 为什么不能只用 random train_test_split？

银行真正的问题是：

```text
用过去 → 预测未来
```

因此后期完整代码采用基于观察日期的时序切分：

```text
Train → Validation → Test
Past                     Future
```

代码中还明确检查每个集合的时间范围和坏样本率，以避免未来信息进入训练集。

## 5.2 Train / Validation / Test

### Train
训练模型参数。

### Validation
用于：

- 模型选择；
- 超参数优化；
- 阈值选择；
- 融合权重；
- 早停。

### Test
用于最终独立评估。

Test 不应参与模型设计。

## 5.3 类别极度不平衡

早期模拟/原型数据中坏样本比例约为千分之几量级。

这意味着如果模型全部预测为好客户，Accuracy 仍然可能超过 99%。

所以：

> Accuracy 不是风控不平衡分类的核心指标。

## 5.4 项目中涉及的不平衡处理方法

### scale_pos_weight

增加正类/坏样本的损失权重。

### Borderline-SMOTE

重点在分类边界附近合成少数类样本。

### ADASYN

在难分类区域自适应生成少数类样本。

### 重要注意

不要同时把过采样和正类权重都设置得过强，否则可能造成 Double Compensation。

### 本课自检

- 为什么只有训练集可以做过采样？
- 为什么 validation/test 不能做 SMOTE？
- 为什么类别不平衡时 Accuracy 会误导？

# 第 6 课：LightGBM、CatBoost、XGBoost 与 Optuna

## 6.1 为什么使用 Boosting Tree？

银行数据主要是结构化表格数据：

- 数值；
- 比例；
- 频率；
- 类别；
- 日期衍生；
- 统计特征。

Boosting Tree 能捕捉：

- 非线性；
- 变量交互；
- 阈值效应；
- 复杂组合关系。

- CatBoost；

典型参数包括：

- subsample；
- colsample_bytree；
- reg_alpha；
- reg_lambda；
- gamma。

### LightGBM
- num_leaves；
- max_depth；
- learning_rate；
- min_child_samples；
- subsample；
- colsample_bytree；

### CatBoost

# 第 7 课：模型评估指标

## 7.1 ROC-AUC

衡量风险排序能力。

直观理解：

> 随机抽一个坏客户和一个好客户，模型把坏客户排在更高风险位置的概率。

## 7.2 KS

项目代码中实现了 KS：

```text
KS = max(|累计坏样本比例 - 累计好样本比例|)
```

用于衡量 Good / Bad 分离能力。

如果 KS 或 AUC 异常接近 1，不能只认为模型非常强，还必须排查：

- 标签泄漏；
- 时间穿越；
- 可疑强特征；
- 重复样本；
- 训练测试重叠。

## 7.3 PR-AUC

在坏样本极少时，比单纯 ROC-AUC 更值得关注。

## 7.4 Precision

```text
TP / (TP + FP)
```

预测为高风险的人中有多少是真的高风险。

## 7.5 Recall

```text
TP / (TP + FN)
```

所有真实坏样本中，模型抓住了多少。

## 7.6 F1

Precision 与 Recall 的综合。

## 7.7 Brier Score

衡量概率预测误差：

```text
mean((predicted_probability - y_true)^2)
```

越低越好。

## 7.8 Top-K Recall

项目代码会检查风险最高的：

- 1%；
- 5%；
- 10%；
- 15%；
- 20%；
- 30%；
- 50%；
- 75%

能够覆盖多少真实坏样本。

这是非常直观的资源投放指标。

### 本课任务

尝试回答：

> 如果银行只能人工复核风险最高的 5% 客户，应该优先看哪个指标？

# 第 8 课：概率校准与模型融合

## 8.1 排序好不等于概率准

AUC 很高只说明风险排序不错。

如果模型说：

```text
一组客户违约概率都为 20%
```

但最终只有 2% 真的违约，则模型概率并不可信。

## 8.2 Platt Scaling

后期代码包含基于 sigmoid 的概率校准思路。

目标是让：

```text
预测概率 ≈ 实际发生率
```

概率校准必须避免使用 test 数据拟合。

## 8.3 Ensemble

三模型分别产生：

```text
P_LGB
P_CAT
P_XGB
```

然后根据 validation 表现得到融合权重：

```text
P_ensemble
= w1 × P_LGB
+ w2 × P_CAT
+ w3 × P_XGB
```

项目代码中权重来源于 validation AUC，而不是 test AUC。

这是正确的模型治理思想。

### 本课任务

解释：

- 为什么 test AUC 不能用来算融合权重？
- 为什么不同模型融合后可能比单一模型更稳？

# 第 9 课：违约概率到 300–900 信用评分

## 9.1 早期线性映射

早期原型使用过类似：

```text
Score = 900 - 600 × P
```

优点：简单直观。

缺点：

当风险概率大量集中在很低区间时，分数会大量挤在 900 附近，区分度较差。

## 9.2 Log-Odds 评分思想

更成熟的评分卡逻辑使用：

```text
Odds = P / (1-P)
```

然后：

```text
Score = A - B × ln(Odds)
```

风险越高：

```text
P ↑ → Odds ↑ → Score ↓
```

风险越低：

```text
P ↓ → Score ↑
```

## 9.3 PDO

后期代码出现：

```text
PDO = 50
```

PDO = Points to Double the Odds。

含义：

> Odds 每翻倍一次，信用评分按固定分值变化。

这是经典评分体系概念。

## 9.4 Score Band

评分可以进一步划分为不同风险等级，例如：

```text
300–900
   ↓
A / B / C / D
```

或者：

```text
高风险
较高风险
一般
低风险
```

风险等级的命名和方向必须与实际业务定义保持一致，不能仅凭字母习惯判断。

## 9.5 Risk Weight

代码中还包含：

```text
Score → Risk Weight [0,1]
```

用于将信用分重新转换为连续风险权重。

### 本课任务

能够完整讲出：

```text
模型特征
→ Default Probability
→ Odds
→ Log Odds
→ Credit Score
→ Risk Band
→ Risk Weight
```

# 第 10 课：稳定性、可解释性与最终交付

## 10.1 Train / Validation Gap

需要检查：

```text
Train AUC
Val AUC
Test AUC
```

如果训练集远高于验证集，可能存在过拟合。

## 10.2 PSI

PSI（Population Stability Index）用于比较不同时间群体的分布稳定性。

核心问题：

> 模型训练时面对的人群，与上线后面对的人群是不是已经发生明显变化？

## 10.3 Score Band Bad Rate

评分完成后，应检查：

> 分数越高，实际坏样本率是否总体下降？

这叫风险单调性。

## 10.4 SHAP

后期代码使用 LightGBM 的 TreeExplainer 生成：

- 全局特征重要性图；
- SHAP Beeswarm 图；
- Top 特征 Dependence Plot。

SHAP 用于解释：

> 为什么模型认为某个客户风险更高或更低？

# 五、必须记住的 12 个关键结论

1. 风控模型首先是业务问题，其次才是算法问题。
2. 标签定义错误，后面的模型再复杂也没有意义。
3. Observation Date 决定什么信息允许进入模型。
4. 单个快照不能自动证明未来标签。
5. 数据泄漏是风控建模最危险的问题之一。
6. 499 个模型维度不等于 499 个业务字段。
7. 类别编码和缺失处理都属于正式特征工程。
8. 时间切分通常比随机切分更符合真实上线环境。
9. 不平衡数据不能只看 Accuracy。
10. AUC 看排序，Brier 看概率，KS 看分离，Top-K 看资源集中效率。
11. 概率、评分、风险等级是三个不同层次的业务表达。
12. 模型最终必须做到可评估、可解释、可监控、可保存。

# 八、最终项目复述模板

当能够不用资料，完整讲出下面逻辑，就说明本次实习已经从“做过”转化为“真正掌握”。

> 银行信用风险模型首先需要确定预测对象、观察时点和未来表现窗口，以观察时点可获得的信息构造特征，根据未来一定时期内是否发生目标风险事件构造 Good/Bad 标签。随后对贷款、客户、余额、利率、期限、还款方式、担保方式、贷款用途等数据进行质量审计，处理缺失值、类别变量，并重点排除未来信息和标签泄漏。

> 为模拟真实上线环境，数据应尽量按时间划分训练集、验证集和测试集，而不是简单随机拆分。针对坏样本比例极低的问题，可以采用样本权重或 Borderline-SMOTE、ADASYN 等方式处理类别不平衡，但只作用于训练数据。
